# OCCT implementation-state audit (rcad/libs)

Generated by `tools/occt-impl-audit/audit.py` (read-only static scan).

## 1. Method

Re-run exactly as:

```bash
uv run python tools/occt-impl-audit/audit.py . --out rcad/docs/occt-impl-audit.md
```

What the scan does:

1. Walks every `*.rs` under `rcad/libs/` (skipping `.mimosa/` session state and
   `target*` build trees) and blanks out comments and string literals with a
   byte-offset-preserving lexer, so brace matching and declaration ranges are
   reliable.
2. Builds a declaration index (`fn` / `struct` / `enum` / `trait` / `impl` /
   `mod` / `type` / `const` / `static`) with body line ranges and `impl` nesting.
3. Extracts every alignment anchor of the form `<OCCT_Class>[.<ext>][::m]
   L<start>[-<end>]` (26k+ sites) and every marker line (`stand-in`, `stub`,
   `placeholder`, `GAP:`, `carrier`, plus a `pending` extension for the
   `pending TKGeomAlgo translation` / `pending-leaf` phrasing used in this repo).
4. Attaches each site to the declaration its comment block documents (the
   nearest following `fn`/`struct`/...) and to the declaration whose body
   contains it, and collects the OCCT-looking names (`[A-Z][A-Za-z0-9]*(_[A-Za-z0-9]+)+`)
   visible in the surrounding comment block and the attached doc block.
5. Joins stand-in/stub sites to real bodies by that class name, and groups
   anchor claims by the OCCT identity `(class, ext, Lstart)` / `(class, ext,
   Lstart, Lend)` to find duplicate translations.

Scanned: 1058 `.rs` files, 6622 non-test sites (8758 including test bodies, which
are reported separately in section 7), 1217 distinct OCCT-like class names.

Honesty note - the heuristics are name- and marker-based, so they can and do
miss things, and they produce false positives. Read the tables as a triage
queue, not as a defect list.

What is *counted*: 4728 non-test sites carry an OCCT anchor, 480 are negative
(stand-in / stub / placeholder / GAP / pending). Of the negative sites, 184
mention no OCCT-looking name at all in their comment window or in the doc of
the item they annotate.

What is therefore **missed**:

- A stand-in whose doc names no `X_Y`-shaped OCCT class is invisible to the
  name join. The `184` nameless negative sites above are exactly that blind
  spot: for example `OCCT Precision::PConfusion stand-in` cannot be joined
  because `Precision` has no underscore.
- A duplicate whose two copies are annotated with *different* OCCT line ranges
  and whose doc blocks do not both lead with the class name will not be paired
  by any of the four joins.
- A hand-rolled stand-in that carries no marker word at all is invisible.
- Classes are joined by exact name (with a `_<digits>` suffix fallback). An
  rcad item that renames the OCCT class will not be paired.

What is **over-reported** (known false-positive families):

- Architecture-difference carriers (section 3c): the rcad-native shape,
  collection, geometry and adaptor layers. Expected, not actionable.
- A genuine external-dependency GAP: an OCCT class this repository truly has
  not translated. It only reaches section 3 when some *other* file claims to
  implement the same class name, but the claim can itself be a cross-reference
  rather than an implementation - rows whose real-body cell says
  `name differs: verify the join` are the ones to distrust.
- Section 4a-ii (`brep_tool_*`, `geom_*`, `topexp_*` helpers copied once per
  module) is rcad's standard kernel-boundary idiom rather than accidental
  duplication.
- Section 4c is a text join on OCCT line ranges and cannot tell a second
  translation from a doc cross-reference; rows marked `low` in `conf` are
  mostly cross-references.
- Method names are matched as bare identifiers, so the `wired?` column is a
  raw token count. A row with a short generic symbol name has a meaningless
  count; `0` is meaningful only for distinctive names.

## 3. Dangerous class: a stand-in/stub over an existing real body

A row means: somewhere in rcad/libs a class is marked as a stand-in/stub/
placeholder/pending translation, while another file claims to implement that
same OCCT class (its doc block *leads* with the class name). `wired?` is the
raw count of references to the stand-in symbol outside its own file; `0` means
the stand-in has no callers at all. Rows are split by confidence: 3a when the
marker line itself names the class (strong), 3b when the class came from a +/-3
line window (weak), 3c when the class is OCCT's own data model (expected).
